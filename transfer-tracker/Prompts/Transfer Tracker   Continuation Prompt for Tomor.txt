# Bonus Rules

## Normal Days — Sunday through Friday

### Approved

* 0–2 = $0
* 3–7 = every approved transfer pays $4.70
* 8+ = every approved transfer pays $5.85

Example:

```text
8 approved
8 × $5.85 = $46.80
```

### Declined

* 0–2 = $0
* 3+ = every declined transfer pays $1.75

---

# Saturday Rules

Saturday is automatically detected from the transfer date.

No toggle.

### Approved

* 0–1 = $0
* 2+ = every approved transfer pays $5.85

### Declined

* 0–2 = $0
* 3+ = every declined transfer pays $1.75

The bonus engine is the single source of truth.

# IMPORTANT NEW REQUIREMENT DISCOVERED

We realized that actual pay stubs show **Approved Bonus and Declined Bonus separately**.

This must be supported.

Approved and declined thresholds are independent.

For example:

```text
3 Approved
2 Declined

Approved Bonus: $14.10
Declined Bonus: $0.00
Total Bonus:    $14.10
```

Another example:

```text
2 Approved
3 Declined

Approved Bonus: $0.00
Declined Bonus: $5.25
Total Bonus:    $5.25
```

Another example:

```text
3 Approved
3 Declined

Approved Bonus: $14.10
Declined Bonus: $5.25
Total Bonus:    $19.35
```

The existing calculation functions already calculate the two categories independently:

```javascript
calculateApprovedBonus()
calculateDeclinedBonus()
```

and `calculateDailyBonus()` currently combines them.

We should NOT rewrite the rules.

Instead, we should make the bonus calculation/data layer expose:

```javascript
{
    approvedBonus,
    declinedBonus,
    totalBonus
}
```

or an equivalent clean structure.

The existing combined bonus should remain available because the dashboard uses it.

# CRITICAL PAYROLL LOGIC

Transfers are ALWAYS logged in IndexedDB.

Being below a threshold does NOT mean the transfer should be deleted or excluded from the database.

Example:

```text
1 approved
2 approved
```

Both transfers remain stored.

If the threshold has not been reached:

```text
Approved Bonus = $0.00
```

When the 3rd approved arrives:

```text
3 approved

Approved Bonus = $14.10
```

The entire group becomes payable.

If one is later deleted:

```text
2 approved

Approved Bonus = $0.00
```

The system must recalculate the entire category from the remaining raw transfers.

Do NOT simply subtract the deleted transfer's individual rate.


Each day currently contains:

```javascript
{
    date,

    approvedCount,
    declinedCount,

```

We will likely need to extend the calculated payroll data to include:

```javascript
approvedBonus
declinedBonus
dailyBonus
```

while preserving:

```javascript
dailyBonus
```

as the combined total.

Weekly data should similarly be able to expose separate Approved and Declined bonus totals while preserving the combined weekly bonus.

Weekly bonus MUST continue to be calculated by summing each day's bonus because thresholds reset daily.

Do NOT calculate weekly bonuses using weekly thresholds.

# Current Bonus Engine

Important existing functions:

```javascript
getBonusRules()
calculateApprovedBonus()
calculateDeclinedBonus()
calculateDailyBonus()
calculateWeeklyBonus()
```

Current `calculateDailyBonus()` essentially does:

```javascript
const approvedBonus =
    calculateApprovedBonus(
        approvedCount,
        rules
    );

const declinedBonus =
    calculateDeclinedBonus(
        declinedCount,
        rules
    );

return approvedBonus + declinedBonus;
```

We should preserve the underlying calculations but expose the separate components.
