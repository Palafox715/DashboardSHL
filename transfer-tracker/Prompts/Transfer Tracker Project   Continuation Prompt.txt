# Bonus Rules

## Normal Days — Sunday through Friday

### Approved

* 0–2 = $0
* 3–7 = every approved transfer pays $4.70
* 8+ = every approved transfer pays $5.85

Example:

```text
8 approved
8 × $5.85 = $46.80
```

### Declined

* 0–2 = $0
* 3+ = every declined transfer pays $1.75

---

# Saturday Rules

Saturday is automatically detected from the transfer date.

No toggle.

### Approved

* 0–1 = $0
* 2+ = every approved transfer pays $5.85

### Declined

* 0–2 = $0
* 3+ = every declined transfer pays $1.75

The bonus engine is the single source of truth.

Do not duplicate bonus calculations in UI code.

---

# Payroll Week

Payroll week is:

```text
Wednesday → Tuesday
```

NOT Monday → Sunday.

Weekly bonus is calculated by summing each day's earned bonus because thresholds reset daily.

# Current Payroll Data Flow

Transfers are grouped by Wednesday → Tuesday payroll week.

`createPayrollWeekData(transfers)` creates:

```javascript
{
    weekStart,
    weekEnd,
    days,
    transferCount,
    weeklyApproved,
    weeklyDeclined,
    weeklyBonus
}
```

Each day contains:

```javascript
{
    date,
    transfers,
    transferCount,
    approvedCount,
    declinedCount,
    dailyBonus
}
```

Weekly bonus is calculated by summing the daily bonuses.

Do not replace this with weekly threshold calculations.

# NEXT PRIORITY

We have officially reached a good stopping point for the current payroll-history milestone.

The next major roadmap item is:

## Phase 4 — Backup

Build:

### 1. Export JSON Backup

Allow the user to export all IndexedDB transfer records into a JSON file.

Example:

```text
transfer-tracker-backup-2026-08-10.json
```

The export must preserve:

* id
* fileNumber
* customerName
* phone
* status
* timestamp

### 2. Import JSON Restore

Allow the user to select a previously exported JSON backup and restore the transfer records into IndexedDB.

Important considerations:

* Validate the JSON structure.
* Reject malformed backup files.
* Preserve timestamps exactly.
* Preserve transfer IDs.
* Avoid accidentally corrupting existing data.
* Handle duplicate IDs safely.
* Do not silently overwrite existing records.
* Give the user clear success/error feedback.

The backup feature should probably live in a simple Settings/Data area rather than cluttering the main dashboard.
